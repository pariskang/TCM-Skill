# TCM-Skill 深度设计方案

> 基于「中醫笈成」CC0 古籍语料(1326 部,数亿字)构建面向 LLM/智能体的
> 「规则 + 技能」系统,目标平台:Claude Code、OpenClaw、Codex 及任意可执行
> shell 的 agent 框架。

---

## 1. 问题定义

LLM 处理中医古籍问题有三个结构性缺陷:

1. **幻觉引文**:模型"背过"经典,但默写会串版本、串书、造句——对文献考证
   是致命的。引文必须可复核。
2. **上下文装不下**:全库数亿字;即使单书(《本草纲目》188 万字)也远超
   上下文窗口。必须检索,不能灌入。
3. **无安全边界**:古籍含剧毒方药、过时疗法;直接复述给有真实用药意图的
   用户是危险的。

因此方案的三根支柱恰好对应:**确定性检索工具**(治幻觉)、**渐进披露技能**
(治上下文)、**常驻规则层**(治安全)。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│ 平台入口层(薄适配,零内容重复)                              │
│  Claude Code: .claude/skills/ 软链 + CLAUDE.md 摘要        │
│  OpenClaw:   ~/.openclaw/skills/(同一 Agent Skills 格式)  │
│  Codex:      AGENTS.md(摘要 + "先读 SKILL.md" 指针)       │
├─────────────────────────────────────────────────────────┤
│ 技能层 skills/tcm-ancient-texts/(单一事实源)               │
│  SKILL.md        入口:铁律 + 工作流 + 速查(~100 行)        │
│  rules/          00核心纪律 10检索策略 20引用规范 30安全红线  │
│  references/     语料概况 / 数据格式(按需加载)              │
│  scripts/tcm.py  统一 CLI(零依赖,stdlib only)             │
├─────────────────────────────────────────────────────────┤
│ 索引层 data/(生成物,不入 git)                             │
│  tcm.db     SQLite:books + paras + FTS5(trigram)         │
│  catalog.json / corpus.jsonl(下游分析、embedding 备用)     │
├─────────────────────────────────────────────────────────┤
│ 数据层                                                    │
│  gitlab.com/jicheng/jc.data(CC0,git 浅克隆,可增量更新)   │
└─────────────────────────────────────────────────────────┘
```

## 3. 关键设计决策与论证

### D1 规则(Rules)与技能(Skill)分离,而非混在一个 prompt 里

- **规则 = 常驻约束**,少量、不可协商:不凭记忆引用、繁体检索、医学红线。
  以两种形态存在:平台常驻文件(CLAUDE.md/AGENTS.md)只放**摘要**,
  完整版在 `rules/` 由 SKILL.md 指路按需读取。
- **技能 = 按需能力**:检索工作流、CLI 用法、异体字表——只在处理古籍任务时
  才值得占用上下文。
- 收益:非古籍任务零 token 开销;古籍任务按深度渐进加载(SKILL.md →
  某个 rule 文件 → reference),这正是 Anthropic Agent Skills 的
  progressive disclosure 设计意图。

### D2 检索用「脚本 + SQLite FTS5」而非向量检索优先

- 古籍考证的主要检索模式是**精确短语/字面命中**("太陽之為病"在哪几本书
  出现、用字有何差异),BM25/精确匹配天然优于语义近似;
- 零依赖(stdlib)、零 API key、离线可用、毫秒级、结果**确定可复现**——
  这对"引文可复核"的核心目标至关重要;向量检索的近似性反而引入不可复现性;
- trigram 分词对无空格古汉语是正确选择;<3 字查询自动回退 LIKE,不漏检;
- 语义检索作为**扩展层**保留(corpus.jsonl 已为 embedding 预留),
  见 §6 路线图——先把确定性的地基打对,再叠加概率性的增强。

### D3 数据不入 git,构建可复现

- 语料克隆 + 索引约 1 GB 量级,入库会毁掉仓库;
- `fetch` 直接浅克隆上游 GitLab(CC0 授权明确),`build` 全程确定性,
  任何机器 5-10 分钟重建;`--sample` 模式 30 秒出可用环境;
- 上游更新 = `git pull` + 重建,天然获得笈成社区的持续校对成果。

### D4 段落为检索原子,`(书, 段号)` 为引用主键

- 解析器把语义 HTML 转为「篇章路径 + 段落」记录,引用格式
  `《书名》·篇章·段号` 三要素同时服务:人类可读、机器可定位、复查可执行;
- 段号由确定性解析顺序生成,重建索引不漂移;
- 保留底本异体字(𤍠/𤼵/隂)不做归一化——**归一化在查询侧**(规则教
  agent 换异体字重试),存储侧永远忠于底本。这是文献工具与普通搜索引擎的
  本质区别。

### D5 繁简转换交给 LLM,不写进脚本

- LLM 本身就是最好的繁简/古今转换器;脚本只做**简体探测 + 提醒**
  (防止静默漏检),不引入 OpenCC 依赖;
- 规则层(00-core R3)把转换责任明确压给 agent,并列出高频陷阱字
  (术/朮、后/後、郁/鬱)。

### D6 跨平台策略:一份内容,三个入口

- Agent Skills(SKILL.md)已是 Claude Code 与 OpenClaw 的共同格式,
  直接复用;Codex 用 AGENTS.md 指针桥接;
- 入口文件只放"摘要 + 指路",细节永远只在 `skills/` 一处,杜绝规则漂移。

### D7 安全设计是规则,不是过滤器

- 30-safety.md 定义不可覆盖的红线:不开方、不换算剂量、毒性药物触发警示、
  十八反十九畏提示、免责声明模板;
- 同时明确"允许什么"(文献层面的完整呈现,包括对有害古方的如实引用 +
  历史局限性说明)——避免过度拒答毁掉学术价值。

## 4. 已验证的端到端效果(真实运行结果)

样本:7 部书(含伤寒宋本、金匮、素问、本草纲目、温病条辨),227 万字,
38263 段,索引 27 MB。

- `search 桂枝湯` → 毫秒级命中,跨 3 书返回带出处片段;
- `search 太陽之為病` → 精确定位宋本伤寒论辨太阳病篇段 144;
- `get "傷寒論(宋本)" --seq 156 --context 2` → 返回桂枝汤方 + 药物组成 +
  煎服法全文,保留底本异体字(𤍠、㣲、煑),带底本信息(赵开美刊本);
- `search 桂枝汤`(简体)→ stderr 提示改用繁体;
- 2 字查询(石膏)自动走 LIKE 回退,命中正常。

## 5. 典型使用场景

| 场景 | 工作流 |
|---|---|
| "伤寒论桂枝汤原文" | search 方名 → get --context → 引文 + 出处 + 免责声明 |
| "各家对'烦躁'的论述对比" | 多书 search --book → 表格对比 + 底本注明 |
| "某方剂最早出处考证" | 全库 search → 按 catalog 年份排序 → 谨慎结论(库的边界要声明) |
| "本草纲目里X药的记载" | search --book 本草綱目 → get --section |
| 定量研究(词频/共现) | build --jsonl → agent 现写分析脚本跑 corpus.jsonl |

## 6. 扩展路线图(按优先级)

1. **MCP Server 封装**(工作量小,收益大):把 search/get/info 包成 3 个
   MCP tool,即可接入 Claude Desktop、任意 MCP 客户端,权限模型更细;
2. **语义检索增强**:corpus.jsonl → 段落 embedding(bge-m3 对古汉语效果好)
   → 与 FTS5 做混合检索(RRF 融合),解决"意思相近但用词不同"的召回;
3. **结构化知识抽取**:方剂表(方名-组成-剂量-主治-出处)、药物别名表——
   用 LLM 批量抽取 + 人工抽检,存 SQLite 新表,支持"含附子的方有哪些"类
   结构化查询;
4. **条文编号对齐**:为宋本伤寒论等核心典籍人工对齐通行条文号(398 条),
   引用更符合学界习惯;
5. **评测集**:构造"引文核对"金标准问答集(N 条已知出处的条文),
   回归验证 agent 是否始终走检索而非记忆。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| agent 绕过工具凭记忆引用 | 铁律置顶 + CLAUDE/AGENTS 常驻摘要双保险;评测集回归(§6.5) |
| 上游语料变动导致段号漂移 | 引用带篇章路径可人工复位;重大更新时 diff catalog |
| 低品质录文误导考证 | 品質字段贯穿 info/规则,强制提醒 |
| 用户带真实用药意图 | 30-safety 红线不可覆盖 + 免责声明模板 |
| Windows 无软链 | install.sh --copy 路径 |
